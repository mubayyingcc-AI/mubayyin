# Customer-controlled runner integration

Mubayyin's intended first integration is a customer-controlled runner, not a provider-credential proxy.

## Data/control boundary

- The customer runs its own model and retains its provider credentials, tool credentials, and execution environment.
- The runner submits a versioned system, scenario definition, and the resulting model output to the invited tenant API.
- Mubayyin evaluates the submitted output against the configured deterministic checks and transparent reference evaluator, then stores tenant-scoped evidence in PostgreSQL.
- Human review and the release decision remain explicit API operations.
- The customer decides what output is approved to submit. Use synthetic data during evaluation; do not send production customer data before security, privacy, retention, and contractual review.

## Python client

A dependency-free Python client is in \`sdk/python/mubayyin_client.py\`.

\`\`\`python
from sdk.python.mubayyin_client import MubayyinClient

client = MubayyinClient(
    base_url="https://mubayyin-web-production.up.railway.app",
    api_key="YOUR_TENANT_KEY_FROM_A_SECRET_MANAGER",
)
print(client.identity())
\`\`\`

Do not hard-code a key in source control, notebooks, browser code, screenshots, or logs. The client requires HTTPS (except loopback testing), does not follow redirects, redacts bearer credentials from errors, and deliberately does not retry POST requests. The current API does not yet expose idempotency keys; a timeout after a POST must be treated as an unknown outcome and checked before manually resubmitting.

## API workflow

1. \`GET /tenant/me\`
2. \`POST /tenant/systems\`
3. \`POST /tenant/scenarios\`
4. \`POST /tenant/trials\`
5. \`POST /tenant/trials/{result_id}/review\`
6. \`POST /tenant/releases\`
7. \`GET /tenant/releases/{record_id}\`
8. \`GET /tenant/releases/{record_id}/export\`
9. \`POST /releases/verify\`

The interactive contract is generated by FastAPI at \`/docs\`; machine-readable OpenAPI is at \`/openapi.json\`. Use Swagger's Authorize control with a tenant bearer key for \`/tenant/*\` calls. Admin provisioning endpoints require the separate administrator token and must not be exposed to partner users.

## Release and security limitations

The reference evaluator is not a semantic Arabic evaluator, regulatory certification, or proof of safety. Scenario-specific canaries are targeted checks, not general-purpose personal-data detection. The tenant workspace is a controlled pilot surface, not an enterprise IAM product. A successful HTTP response alone does not prove the entire workflow is durable: test with an invited tenant, then verify retrieval after a Railway process restart and verify two-tenant isolation before using customer data.
