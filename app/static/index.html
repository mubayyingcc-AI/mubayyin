Programme alignment · preliminary

START pathway is the relevant target to assess

Startup Qatar describes START for technology startups with a proof of concept or MVP seeking to establish operations in Qatar. Its published criteria include:

  • Validated concept addressing an unmet market need
  • Clear execution plan and detailed technology roadmap
  • Market research and a credible business model
  • Clear monetisation strategy
  • Committed leadership team with relevant experience

This is an alignment checklist, not an endorsement, eligibility confirmation or funding promise. Mubayyin must substantiate each point with evidence and satisfy the programme's formal application requirements.

A decision system, not another score

Evidence that travels with the release.

A single score can hide what was tested, which rule failed, or where the evidence stopped. Mubayyin is being built around explicit scenarios, inspectable findings, and a versioned Release Record.

01

Test against expectations

Define expected and forbidden behaviour, risk level, escalation needs, and required disclosures before running a trial.

02

Trace the evidence

Keep configuration identity, deterministic checks, findings, and evidence hashes connected to the test result.

03

Make the decision explicit

Separate test outcomes from release approval. Critical failures and missing evidence should not be hidden by a reassuring aggregate score.

Designed for inspectability

What the current engine can—and cannot—prove.

Trust begins with clear boundaries. The public test lab uses the current deterministic checks and a simple reference evaluator; it is not a production certification or a substitute for expert review.

✓

Implemented in the current engine

Explicit forbidden-phrase checks, required-disclosure checks, escalation phrase checks, scenario configuration, configuration hashes, evidence hashes, and release-gate logic.

△

Known limitations

The reference judge uses lexical overlap, not an independent language model. Phrase matching does not understand semantic paraphrases. PostgreSQL evidence persistence is implemented when configured, but restart/restore durability has not yet been independently verified. Authentication and tenant isolation are not implemented.

→

Next engineering gates

Database-backed restart/restore verification, authentication and tenant isolation, robust privacy detection, customer-defined scenario packs, complete report export, and payment integration.
